# Como contribuir com o projeto no GitHub

## Commits

Prefira commits pequenos e descritivos:

- `docs: adiciona persona P02`
- `docs: revisa cenário C01 após feedback`
- `assets: adiciona HTA da tarefa T03`
- `eval: consolida violações heurísticas`
- `docs: define escopo de IHC para DBA`
- `docs: revisa H02 após entrevista`
- `design: adiciona histórico filtrável rastreado a T03`

Evite commits como `alterações`, `final`, `coisas novas`.

## Branches (opcional)

Se a equipe usar branches, prefira: `entrega/05-analise-tarefas`, `fix/molic-cenario-02`.

## Pull requests

Ao abrir uma revisão, use o template em `.github/PULL_REQUEST_TEMPLATE.md`. O objetivo é tornar explícito o que foi alterado, por quem e qual feedback motivou a mudança.

## Autoria acadêmica

Histórico de Git não substitui a identificação de autoria dentro da entrega. Em atividades individuais, mantenha o nome/matrícula junto ao artefato.

## Mudanças de escopo

Quando uma evidência levar a equipe a mudar usuário prioritário, objetivo ou recorte de interface, registre a decisão em `RASTREABILIDADE.md`. Não apague silenciosamente a hipótese anterior. A mudança do **escopo de IHC da disciplina** não implica, por si só, mudança do escopo formal do TCC.
